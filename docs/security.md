# Безопасность: шифрование и обмен ключами

EMI шифрует трафик через AES-256-GCM (AEAD: конфиденциальность + аутентификация данных).
Ключ сессии **никогда не передаётся по сети открытым текстом** — его согласует выбранная
стратегия `IKeyExchange`. Уровень защиты выбирается под вашу инфраструктуру и модель угроз.

## Лестница уровней

| Уровень | Стратегия | Защищает от | Требует |
|---|---|---|---|
| **0. Off** | `UseEncryption = false` | — | ничего. Доверенная сеть (LAN), прототип, или транспорт уже шифрует сам (Steam P2P) |
| **1. PSK** | `PreSharedKeyExchange` | пассив + активный MITM | раздать общий ключ вне сети (зашить в билд/конфиг) |
| **2. RSA inline** | `RsaKeyExchange.CreateClient()` (дефолт) | **только пассивную прослушку** | ничего, zero-config |
| **3. RSA pinned** | `RsaKeyExchange.CreateClientPinned(pub)` | пассив + **активный MITM** | положить публичный ключ сервера в клиент |

Ключ уникален на каждое соединение (кроме PSK, где он общий по замыслу).

## Как выбрать уровень

- **Доверенная сеть / транспорт уже шифрует** (Steam P2P, TLS-туннель) → уровень 0.
- **Нужно быстро закрыть прослушку, инфраструктуры под ключи нет** → уровень 2 (дефолт при `UseEncryption = true`).
- **Клиент и сервер — части одного продукта, важна защита от MITM** → уровень 3 (пиннинг).
- **Ключ можно безопасно раздать заранее** (доверенный канал, один оператор) → уровень 1 (PSK).

## Уровень 2: RSA inline (по умолчанию)

Просто включите шифрование с обеих сторон:

```csharp
// Сервер
server.UseEncryption = true;   // KeyExchange создастся автоматически (RSA)
server.Start("127.0.0.1#9000");

// Клиент
client.UseEncryption = true;   // доверяет публичному ключу из handshake
await client.Connect("127.0.0.1#9000", token);
```

Клиент генерирует случайный AES-256 ключ и шлёт его серверу под публичным ключом сервера
(RSA-OAEP-SHA256). Расшифровать может только сервер своим приватным ключом. Пассивный
слушатель видит только шифртекст.

> **Важно:** уровень 2 НЕ защищает от активного MITM. Атакующий, стоящий в середине,
> может подменить публичный ключ сервера на свой. Если это в вашей модели угроз — уровень 3.

## Уровень 3: RSA с пиннингом (защита от MITM)

Сервер держит стабильную RSA-пару; клиент заранее знает её публичную часть и сверяет.

```csharp
// СЕРВЕР: один раз сгенерировать пару, приватный ключ сохранить (в секрете!)
var kex = RsaKeyExchange.CreateServer();
byte[] publicKey  = kex.ExportPublicKey();    // раздать клиентам (можно в открытую)
byte[] privateKey = kex.ExportPrivateKey();   // ХРАНИТЬ В СЕКРЕТЕ

server.UseEncryption = true;
server.KeyExchange = kex;                      // стабильная пара между рестартами:
                                               // RsaKeyExchange.CreateServer(privateKey)
server.Start("127.0.0.1#9000");

// КЛИЕНТ: пиннит публичный ключ сервера
client.UseEncryption = true;
client.KeyExchange = RsaKeyExchange.CreateClientPinned(publicKey);
await client.Connect("127.0.0.1#9000", token);
```

Если полученный от сервера публичный ключ не совпадёт с закреплённым — handshake упадёт
с ошибкой (возможный MITM), соединение не устанавливается.

## Уровень 1: Pre-Shared Key

Ключ роздан обеим сторонам заранее и **по сети не передаётся вообще** — перехватывать нечего.

```csharp
byte[] shared = /* 16, 24 или 32 байта, розданы вне сети */;

// обе стороны
server.UseEncryption = true;
server.KeyExchange = new PreSharedKeyExchange(shared);

client.UseEncryption = true;
client.KeyExchange = new PreSharedKeyExchange(shared);
```

Единственное требование — доставить ключ обеим сторонам безопасным способом.

## Шифрование в Headless / Steam P2P

`HeadlessHandler` не владеет соединением и не имеет управляемого библиотекой handshake-раунда,
поэтому уровни 2/3 (которым нужен обмен по сети) там **недоступны**. Варианты:

- **PSK** — ложится идеально, ключ не требует переговоров:
  ```csharp
  headless.UseMiddleware(new AesGcmMiddleware(sharedKey));
  ```
- **Ничего** — часто внешний транспорт уже шифрует (Steam P2P шифрует трафик между пирами сам),
  и второй слой поверх — лишняя трата CPU.

## Forward secrecy

RSA key-transport (уровни 2–3) **не даёт forward secrecy**: если приватный ключ сервера
когда-нибудь утечёт, ранее записанный трафик можно расшифровать задним числом. Для игрового
трафика это обычно приемлемо. Если forward secrecy нужна — реализуйте `IKeyExchange` поверх
ECDHE (эфемерные пары на каждое соединение); абстракция это позволяет без изменения остального кода.

## Свой обмен ключами

`IKeyExchange` — публичный интерфейс. Обмен укладывается в один round-trip handshake:
сервер шлёт `ServerOffer()`, клиент отвечает `ClientComplete(...)`, сервер завершает
`ServerComplete(...)`. Так можно добавить ECDHE, Steam-тикеты, свой PKI — не трогая RPC и транспорт.
